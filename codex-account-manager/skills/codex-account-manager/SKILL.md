# Codex Account Manager

Use the account_manager tools for this workflow. Prefer this manager over the older Codex Account Rotator, which copies stale auth snapshots and cannot coordinate an app restart.

- The Show stats for selector in the detail header supports All accounts or one saved account and remembers the selection. With no valid individual selection it defaults to All accounts. All accounts overview in the sidebar opens the combined view. Combined token cards/chart use deduplicated account-wide history or the full local ledger, including retained and unassigned history. Quota and account actions are shown for individual accounts only.
- The Focus dashboard has a searchable account sidebar and a separate selected-account detail pane. Selecting an account only changes the displayed details; Switch & reopen changes the actual login. Ellipsis menus provide Rename, Refresh, Reconnect, and Remove. Screenshot privacy at the bottom of the sidebar masks names, emails and identifying initials; it does not remove account data or hide usage figures. Token charts support Today/7/30-day and available all-time history; This Mac and Account-wide select independent data sources. Reset redemption remains in Codex’s account menu.
- The Live sessions sidebar view reads local task lifecycle, model, reasoning effort, input/cache/output tokens and estimated USD cost. It refreshes about every 5 seconds; initial session history imports in bounded batches, with partial counts labeled. Up to 100 sessions updated in the last 7 days are listed; each total spans that session’s imported history, potentially across models and accounts. The account label is for the latest observed turn only. Unknown account attribution remains unassigned. Active means an open turn with a log signal within 2 minutes; silent turns show No recent signal, not a definitive running/finished claim. Costs use the dated Standard API pricing table in scripts/session-pricing.json, with cache and long-context rates; unavailable models remain N/A or partial. These are API-equivalent estimates, not subscription charges, and exclude tool charges, Fast mode and regional surcharges. Screenshot privacy also masks session titles and projects. No reasoning text or prompt content is persisted by this reader.
- `account_manager_open` returns the dashboard URL. Open it with the Codex browser panel when the user wants visual management. Keep the tab as a deliverable.
- `account_manager_list` returns saved account identity and last checked usage. Missing values are N/A, never zero. `stale: true` means these values are not a current successful check.
- `localUsage` is this Mac's durable token ledger: per-account `periods`, combined `totals`, and `daily` rows. It survives saved-profile removal and reconnects by identified account. It reads local OpenAI Codex rollout events, independently of account-wide API counts. Old logs lack account IDs; show them as Unassigned local history. New attribution uses observed selection at turn start; gaps or ambiguous switches stay unassigned. Include unassigned tokens in the Mac total, never silently distribute them among accounts. `pendingBytes` means historical import is incomplete; `error` means recording needs attention. UTC Today/7/30-day periods include today; All recorded covers available imported logs plus subsequent recordings. The recorder runs while the dashboard service runs, even with its browser closed; open the launcher after reboot to resume. It stores counters and metadata, not prompts.
- Token counts are in each account's `tokenPeriods` and the combined `tokenSummary.periods`: `today`, `days7`, `days30`, and `allTime`. Today uses UTC calendar dates; 7 and 30 days include today. Daily periods sum provider-reported buckets; all time uses the provider's lifetime total. A missing current-day bucket is Not reported, not zero; only an explicit zero bucket establishes zero account-wide usage today. This Mac remains the independent local source. Do not infer token counts from quota percentages. Report incomplete coverage and stale snapshots. Combined totals deduplicate identified accounts; unavailable accounts are not assumed to have zero usage. Use Refresh usage to update token history as well as quotas.
- `account_manager_refresh` queues live checks for all saved accounts or an `id`, without changing the selected account. Read the dashboard or list again after the check; slow accounts may still be pending. Window duration comes from the response: never assume the primary window is 5 hours. Reset-credit availability is distinct from scheduled window resets and purchased credit balance.
- `account_manager_save_current` saves the current login under `label`. Account identity comes from Codex's account protocol, not decoded credential files.
- `account_manager_rename` changes a saved account display name using `id` and `label`, preserving credentials, identity, and token history.
- `account_manager_remove` removes the specified saved `id` and its saved session. Use only when the user asks to remove that account. Local token history is retained. The current app login, conversations, and previous recovery backups remain unchanged. The dashboard shows an account-specific confirmation before removal.
- `account_manager_connect` starts normal ChatGPT sign-in. Open the returned authorization link for the user to complete sign-in. Do not ask for passwords or tokens in chat. It adds the account without logging the running app out. Passing an existing `id` reconnects that profile.
- `account_manager_switch` requires the exact saved `id` and `reopen: true`. State that it closes and reopens the desktop app. Only invoke it when the user has requested the switch now; creating or testing the plugin is not authorization to interrupt ongoing work. The implementation validates the target, gracefully quits, saves the final outgoing session, changes auth, and reopens. It never force-kills the desktop app. The response first acknowledges a queued switch; check its final status before claiming completion.

Use the dashboard's Switch & reopen button for user-driven switches. Check that the app is using the expected account after reopening. Account Manager keeps the same Codex home and does not edit conversations, history, workspaces, or settings. Reopening can interrupt running tasks; saved conversations are distinct from in-flight work.

Credentials remain local in `~/.codex-account-manager/` with owner-only permissions. Treat auth files as opaque; never print or decode them. Checks allow Codex itself to refresh sessions and persist the result. Invalid logins require normal sign-in again; do not claim they can be recovered without it. Do not use old rotator commands against these sessions.

The manager only reads reset availability. If the user explicitly asks to redeem a reset, use the app's existing `consume_usage_reset` tool for the signed-in account after checking identity. Do not automatically spend reset credits when showing usage or switching.

CLI fallback: `node ~/plugins/codex-account-manager/scripts/account-manager.cjs open`, `list`, `refresh`, `save <label>`, `connect <label>`, or `import-legacy`. The installed plugin includes no account credentials. A new Codex thread may be needed to discover newly installed MCP tools.
